# Security Policy

## Supported version

Security fixes are applied to the latest release on the `main` branch.

## Reporting a vulnerability or accidental disclosure

Do not open a public issue for vulnerabilities, credentials, private paths, embargoed data, or unpublished collaboration material. Contact the repository owner privately through the contact method on the owner's GitHub profile and provide:

- the affected version or commit;
- a minimal description of impact;
- reproduction steps that contain no real secrets or restricted data; and
- a safe way to coordinate remediation.

The maintainer will acknowledge a credible report, assess scope, remove exposed material where possible, rotate affected credentials when applicable, and publish a fix or advisory proportionate to the risk.

## Scientific safety is separate

A questionable physical conclusion, calibration choice, or uncertainty model is normally a scientific-validity issue rather than a software-security vulnerability. It should still be reported, but no output from this project should be used as an automatic safety-critical, clinical, regulatory, or publication decision.
